# Фронт: как страница выглядит и ведёт себя у посетителя

Проверки в браузере (Playwright, Chromium), как у [сверки с макетом](../design/README.md). Ловят то, что не видно без браузера: ошибки JavaScript, вёрстку на разных ширинах, сломанные вкладки, карусели и формы.

> Статус: **каркас**. Папка, формат описания и план проверок готовы, кода и пайплайна пока нет.

## Что будет проверяться

| Проверка | Что ловит |
|---|---|
| Ошибки JavaScript | сообщения `error` в консоли и необработанные исключения на каждой странице из списка |
| Адаптив | горизонтальная прокрутка, обрезанные блоки и наложения на ширинах 375 / 768 / 1280 |
| Сценарии | вкладки переключаются, карусели листаются, меню открывается, календарь листает месяцы |
| Формы — интерфейс | обязательные поля, маски, сообщения об ошибках; **без отправки** (отправка — в [бэке](../backend/README.md)) |
| Скорость глазами пользователя | Lighthouse / Web Vitals (LCP, CLS) по ключевым страницам, с порогами |

Сверка вёрстки с макетом Figma — тоже фронт, но живёт отдельно в [design/](../design/README.md): у неё свои данные (макеты) и свой пайплайн.

## Где описание для сайта

```
projects/<ключ>/frontend/
  scenarios.yml     страницы, ширины, сценарии
```

Формат — в примере `projects/_template/frontend/scenarios.yml`. Адрес сайта, как и везде, берётся из секрета `SITE_<КЛЮЧ>`, в файле только пути.

## Как это ляжет дальше

| Что | Где |
|---|---|
| CLI слоя | `frontend/frontend_checks.py` (по образцу `design/design_compare.py`) |
| общий код | `common/sitecheck/frontend*.py` |
| пайплайн | `.github/workflows/frontend-checks.yml`: ручной запуск, матрица «сайт × страница», отчёт в общем формате |
| зависимости | `requirements-design.txt` (Playwright уже там) |
