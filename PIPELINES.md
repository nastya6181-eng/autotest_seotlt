# Пайплайны: как запускать

Все пайплайны во вкладке **Actions** репозитория, список слева.

## Какие есть

| Пайплайн | Что проверяет | Как запускается |
|---|---|---|
| **Common checks** | сайты целиком: техника, SEO, ссылки, орфография, типографика | вручную |
| **Design checks** | вёрстку страниц против макетов Figma | вручную |
| **Metrics** | собирает дашборд: дефекты, задачи, прогоны | сам, после Common/Design checks и при изменении задач; можно вручную |
| **Lint** | код и настройки репозитория: Python, YAML, файлы пайплайнов | сам, на каждом PR и после мержа в `main` |
| **Self-test** | тесты самих проверок и настройки сайтов в `sites/` | сам, на каждом PR и после мержа в `main` |

Сайты запускаются вручную только через **Common checks** и **Design checks**. Остальные три работают сами.

## Как запустить

1. Actions → слева выбрать **Common checks** (или **Design checks**).
2. Справа кнопка **Run workflow** → ветка `main`.
3. Заполнить поля (ниже) или оставить пустыми → зелёная кнопка **Run workflow**.
4. Через несколько секунд сверху появится прогон. Название говорит, что запущено: `Common checks · lazun`, `Design checks · innotech · main`.

Если прогон встал в **Action required**, его должна подтвердить владелица репозитория: открыть прогон → **Approve and run**.

### Поля Common checks

| Поле | Что вписать | Пусто |
|---|---|---|
| `site` | ключ сайта: `innotech`, `lazun`; или `all` | `all` — все сайты |
| `max_pages` | сколько страниц обойти, например `20` | из настроек сайта или 200 |
| `checks` | какие тесты, через запятую: `tech`, `seo`, `links`, `spelling`, `typography` | все пять |

### Поля Design checks

| Поле | Что вписать | Пусто |
|---|---|---|
| `site` | ключ сайта или `all` | `all` |
| `page` | страница из `sites/<ключ>/design/pages.yml` (поле `name`), например `main` | все страницы с макетами |
| `tolerance` | допуск по положению в пикселях, например `4` | из `pages.yml` или 2 |

## Готовые рецепты

| Хочу | Пайплайн | Поля |
|---|---|---|
| Всё по всем сайтам | Common checks, потом Design checks | всё пустое |
| Всё по одному сайту | Common checks | `site=lazun` |
| Только ссылки на лазуне | Common checks | `site=lazun`, `checks=links` |
| Ссылки и SEO на иннотехе, быстро | Common checks | `site=innotech`, `checks=links,seo`, `max_pages=20` |
| Только орфографию по всем | Common checks | `checks=spelling` |
| Одну страницу макета | Design checks | `site=innotech`, `page=main` |
| Пересобрать дашборд | Metrics | — |

**Вместе.** Common checks и Design checks можно запустить один за другим, не дожидаясь первого: они идут параллельно. При `site=all` сайты внутри одного прогона тоже проверяются параллельно (до 4 сразу). Пайплайна «запустить всё» нет: это два разных запуска.

## Что сейчас идёт и где результат

Прогон делится на три этапа, их видно на схеме прогона:

```
infra  →  tests (lazun), tests (innotech) …  →  logs
```

- **infra** — подготовка: зависимости, словари, список сайтов. В логе шага «Список сайтов»: `Сайтов: 2 — innotech, lazun`.
- **tests (<сайт>)** — проверка одного сайта. Внутри шаги: «Обход сайта», затем «Тест: техника», «Тест: SEO», «Тест: ссылки», «Тест: орфография», «Тест: типографика». Какой шаг крутится, тот тест сейчас и идёт. Пропущенные (не попали в `checks`) — серые.
  В Design checks задание называется `design (<сайт> · <страница>)`, тест в нём один — «Тест: макет».
- **logs** — собирает всё вместе: общая сводка, вкладка Checks, история для дашборда.

**Где смотреть итог:**

| Место | Что там |
|---|---|
| Прогон → **Summary** | сводка по сайтам; по каждому правилу — как исправить, на каких страницах, где на странице и где править |
| Задание → шаг **«Тест: …»** | лог одного теста: какие правила ✔ / ✘ и подробности |
| Прогон → **Artifacts** | `report-<сайт>` с `findings.csv` (все замечания, открывается в Excel); `logs-all` — всё одним архивом |
| Значок ✘ / ✔ у прогона | красный — нашлись дефекты или что-то сломалось; что именно, видно в Summary |

## Запуск у себя на компьютере

Нужен Python 3 и файл `.env` со списком сайтов (`cp .env.example .env`, адреса — у владелицы репозитория).

```bash
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt

./venv/bin/python checks/content/run_checks.py --list                    # какие сайты есть
./venv/bin/python checks/content/run_checks.py --site lazun              # всё по одному сайту
./venv/bin/python checks/content/run_checks.py --site lazun --only links # один тест
```

Один тест много раз, без повторного обхода сайта:

```bash
./venv/bin/python checks/content/run_checks.py --site lazun --stage crawl               # 1 раз: обход
./venv/bin/python checks/content/run_checks.py --site lazun --stage test --only links   # сколько угодно раз
./venv/bin/python checks/content/run_checks.py --site lazun --stage report              # сводный отчёт
```

Результат — в `reports/<сайт>/`, тот же отчёт печатается в терминал. Сверка с макетом локально — в [checks/design/README.md](checks/design/README.md).
