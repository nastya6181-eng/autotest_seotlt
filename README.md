# Автотесты сайтов SEOTLT

[![Common checks](https://github.com/nastya6181-eng/autotest_seotlt/actions/workflows/common-checks.yml/badge.svg)](https://github.com/nastya6181-eng/autotest_seotlt/actions/workflows/common-checks.yml)

Автоматические проверки клиентских сайтов. Общие проверки (орфография, типографика, ссылки)
лежат в `common/` и работают для любого сайта. Какие сайты проверять, задаётся переменными
окружения `SITES` и `SITE`; в GitHub список хранится секретом, в репозитории адресов сайтов нет.
Папка в `projects/` нужна, только если у сайта объёмные свои настройки
или, со временем, свои проверки.

## Структура

```
common/                   общие проверки для всех сайтов
  run_checks.py           точка входа
  list_sites.py           список сайтов в JSON для пайплайна
  sitecheck/
    crawler.py            обход сайта (один проход на все проверки)
    tech.py               robots.txt, SSL, https, мягкий 404, sitemap
    seo.py                noindex, title, description, H1, alt, смешанный контент
    throttle.py           бережный темп запросов и пауза после бана
    spelling.py           орфография: словари Hunspell ru_RU + en_US
    typography.py         пробелы, дефисы и тире, кавычки, пунктуация
    links.py              битые ссылки, кривые href, якоря, редиректы
    report.py             отчёты: md, csv, json, JUnit
    sites.py              разбор SITES / SITE / .env
  dictionaries/ignore.txt слова-исключения для всех проектов
.env.example              пример переменных для локального запуска
projects/
  _template/              шаблон нового проекта
  <ключ>/                 необязательные настройки сайта (без адреса)
tests/                    самопроверка правил
.github/workflows/        расписание и пайплайн
```

## Что проверяется

| Проверка | Правила | Уровень по умолчанию |
|---|---|---|
| Техника (весь сайт) | robots.txt закрывает сайт (`Disallow: /`), SSL истекает меньше чем через 14 дней или не проходит проверку | **error** |
| | SSL истекает меньше чем через 30 дней, `http://` не ведёт на `https://`, несуществующая страница отвечает 200 («мягкий 404»), нет sitemap.xml | warning |
| | нет robots.txt | info |
| SEO (каждая страница) | `noindex` в meta или `X-Robots-Tag`, нет `<title>`, смешанный контент (`http://`-ресурсы на `https://`-странице) | **error** |
| | одинаковый title на разных страницах, нет meta description, нет H1, картинка без `alt` | warning |
| | длина title вне 10–70 символов, одинаковый description, несколько H1, нет `<html lang>` | info |
| Ссылки | страница не открылась, битая внутренняя ссылка или ресурс, кривой href (пустой, телефон без `tel:`, адрес без `https://`, почта без `mailto:`, пробел, сломанный протокол) | **error** |
| | битая внешняя ссылка, заглушка `#`, пропавший якорь | warning |
| | редирект, внешняя ссылка в той же вкладке | info |
| Орфография | слово не найдено в словаре (с подсказкой) | warning |
| Типографика | повтор слова, пробел перед знаком, нет пробела после запятой или точки, двойная пунктуация, латиница в русском слове, прямые кавычки, дефис вместо тире, тире без пробелов, висячий дефис, пробел внутри скобок | warning |
| | три точки вместо «…», диапазон чисел через дефис | info |

Тесты строгие. Тест (правило) красный, если по нему есть хотя бы один дефект, даже если сейчас падает почти всё: нужна полная картина, а исправлять будут по приоритету. Уровень означает именно приоритет:

- **error** — критично: сайт сломан для посетителя или выпал из поиска. Чинить первым.
- **warning** — дефект текста, вёрстки или SEO. Тест тоже красный.
- **info** — рекомендация. На статус не влияет, видна в отчёте.

Ложное срабатывание лечится не понижением уровня, а исключением: слово в `ignore.txt`, адрес в `links.ignore`, правило `off` для конкретного проекта, если оно к нему не относится.

Уровень любого правила можно поменять для проекта в `severity:` своего `project.yml`, в том числе выключить правило (`off`). Какие уровни делают тест красным, задаёт `fail_on` (по умолчанию `[error, warning]`).

## Переменные окружения

| Переменная | Что задаёт | Пример |
|---|---|---|
| `SITES` | все сайты для прогона, по строке на сайт: `ключ=адрес [опция=значение …]`. В GitHub — **секрет** | `site-a=https://example.ru/ max_rps=0.8` |
| `SITE` | прогнать один сайт: ключ из `SITES` или любой адрес, даже не из списка. Пусто или `all` — все | `site-a`, `https://example.ru/` |
| `MAX_PAGES` | лимит страниц на сайт | `30` |
| `CHECKS` | только эти проверки: `tech,seo,links,spelling,typography` | `links,typography` |
| `MAX_RPS` | не чаще N запросов в секунду к сайту | `0.8` |

Ключ — это имя сайта в отчётах, issues и Checks. Его видят все, кто открывает репозиторий, поэтому лучше нейтральный ключ, не совпадающий с названием клиента. Без ключа он строится из домена.

Опции в строке `SITES`, все необязательные:

| Опция | Что делает |
|---|---|
| `max_pages=300` | лимит страниц обхода |
| `delay=0.5` | пауза между страницами при обходе, с |
| `max_rps=0.8` | не чаще N запросов в секунду к сайту. Нужна, если сайт банит за частые запросы (429 или 503 «too many requests») |
| `cooldown=330` | сколько ждать, если сайт всё же забанил, с |
| `ignore_robots=true` | не соблюдать robots.txt. Только для своих сайтов или по заданию владельца |
| `exclude=calendar/\?date=` | регэксп адресов, которые не обходить |
| `workers=2` | параллельных проверок ссылок |

Объёмные настройки (исключения орфографии, уровни правил) кладутся в `projects/<ключ>/project.yml` под тем же ключом. Адреса в этом файле нет.

Порядок важности: флаги → `MAX_PAGES` / `MAX_RPS` / `CHECKS` → опции из `SITES` → `projects/<ключ>/project.yml` → умолчания.

## Запуск у себя

```bash
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
cp .env.example .env                       # список сайтов; .env в git не попадает

./venv/bin/python common/run_checks.py                                   # все сайты из SITES
SITE=site-a ./venv/bin/python common/run_checks.py                       # один сайт
SITE=https://example.ru/ MAX_PAGES=30 ./venv/bin/python common/run_checks.py
SITE=site-a CHECKS=links ./venv/bin/python common/run_checks.py          # только ссылки
./venv/bin/python common/run_checks.py --list                            # какие сайты возьмутся
python3 -m unittest discover tests                                       # самопроверка
```

То же можно задать флагами `--site`, `--max-pages`, `--only`.

Отчёт появится в `reports/<ключ>/`:

| Файл | Что внутри |
|---|---|
| `report.md` | сводка: замечание, сколько страниц затронуто, пример страницы, контекст |
| `findings.csv` | все замечания построчно, открывается в Excel |
| `summary.json` | цифры прогона, из них строится история |
| `junit.xml` | результат в формате тестов для GitHub Checks |

Словари Hunspell скачиваются при первом запуске в `common/.cache/dict`.

## Новый сайт

Добавь строку `ключ=https://адрес/` в `SITES`: в GitHub — в секрет, локально — в `.env`. Со следующего прогона сайт проверяется общими проверками. Лимиты и `ignore_robots` пишутся опциями в той же строке.

Своя папка нужна для объёмных настроек: исключения орфографии, уровни правил, параметры проверок.

1. Скопируй `projects/_template` в `projects/<ключ>`. Ключ тот же, что в `SITES`: латиница, без пробелов.
2. Поправь нужные настройки. Адрес и название клиента в файл не пиши.
3. Закоммить.

Ложные срабатывания орфографии лечатся словами в `projects/<ключ>/ignore.txt`. Например, «технопарк*» со звёздочкой покрывает все формы слова. Слова, общие для всех проектов, пишутся в `common/dictionaries/ignore.txt`.

Проверки, нужные только одному проекту, кладутся в его папку. Пример: форма заявки или калькулятор.

## Пайплайн

Общие проверки идут одним пайплайном `.github/workflows/common-checks.yml` из трёх этапов:

```
infra ──► tests (site-a) ─┐
      ├─► tests (site-b) ─┼─► logs
      └─► tests (…)      ─┘
```

| Этап | Что делает |
|---|---|
| **infra** — инфраструктура | ставит зависимости, прогоняет самопроверку правил, скачивает и кэширует словари, собирает список сайтов из секрета `SITES` и поля `site`. В матрицу уходят только ключи |
| **tests** — чанк на каждый сайт, до 4 параллельно | шаг «Обход сайта» сохраняет страницы, затем отдельными шагами идут тесты «техника», «SEO», «ссылки», «орфография», «типографика» по этому обходу; шаг «Отчёт по сайту» собирает результат. Красный шаг сразу показывает, какой тест упал на каком сайте |
| **logs** — сборщик логов | забирает результаты всех чанков, пишет общую таблицу по сайтам, выкладывает одним архивом `logs-all`, публикует тесты во вкладку Checks, ведёт issues и дописывает историю |

Внутри чанка у каждого теста свой лог: `logs/crawl.log`, `logs/links.log` и т. д. Каждое правило теста отдельно видно в Checks (8 правил техники, 11 SEO, 8 ссылок, 1 орфографии, 13 типографики).

Новая общая проверка добавляется так: модуль в `common/sitecheck/`, строка в `CHECKS` в `run_checks.py` и шаг «Тест: …» в этапе tests.

Когда запускается:

| Когда | Что делает |
|---|---|
| по расписанию, пн–пт 07:00 МСК | полный обход всех сайтов из `SITES` |
| вручную (Actions → Common checks → Run workflow) | поле `site`: ключ, любой адрес или `all`; также лимит страниц и тесты |
| при пуше в `main`, если менялись `common/`, `projects/` или `tests/` | быстрый прогон на 20 страницах, без issue и истории |

### Секрет SITES

Список сайтов хранится секретом репозитория: Settings → Secrets and variables → Actions → **Secrets** → New repository secret, имя `SITES`. Значение — по строке на сайт, формат как выше:

```
site-a=https://example.ru/ max_pages=300
site-b=https://example.com/ max_rps=0.8 cooldown=330 ignore_robots=true
```

- Значение секрета после сохранения не видно никому, даже владельцу. Его можно только перезаписать целиком, поэтому держи копию у себя.
- Сайт добавляется или убирается перезаписью секрета, коммит не нужен.
- Без секрета пайплайн падает на этапе infra с подсказкой.
- Адреса и домены сайтов маскируются в логах заданий (`***`). В матрицу, сводки и issues попадают только ключи.

**Что секрет не скрывает в публичном репозитории.** Артефакты прогона (`report.md`, `findings.csv`, логи с адресами страниц) и Checks может скачать любой посетитель. Чтобы результаты видела только команда, сделай репозиторий приватным: Settings → General → Danger Zone → Change visibility. Actions в приватном репозитории бесплатны в пределах 2000 минут в месяц.

Расписание меняется строкой `cron` в workflow. Время указывается в UTC.

### Где смотреть результаты

| Где | Что видно |
|---|---|
| Бейдж выше | состояние последнего прогона |
| Actions → прогон → Summary | общая таблица по сайтам от сборщика и подробная сводка каждого чанка |
| Actions → прогон → Artifacts | `logs-all`: логи и отчёты всех сайтов; `report-<ключ>`: результат одного чанка вместе с сохранённым обходом. Хранятся 90 дней |
| Checks у коммита | «Общие проверки сайтов»: каждое правило каждого сайта показано как тест, зелёный или красный |
| Issues с метками `autotest` и `site:<ключ>` | открыт, пока у сайта есть ошибки; каждое новое падение добавляется комментарием, закрывается сам после зелёного прогона |
| Ветка `metrics`, файлы `history/<ключ>.csv` | одна строка на прогон: страницы, ошибки, предупреждения и разбивка по правилам. GitHub показывает CSV таблицей, её можно забрать в Google Sheets для графика |

Письма о красных прогонах по расписанию GitHub шлёт автору последней правки `cron`. Остальным участникам письма о новых issue приходят, если они подписаны на репозиторий (Watch).

### Если сайт не открывается из GitHub

Раннеры GitHub стоят за рубежом, а часть российских сайтов режет зарубежные IP. Признак — `page_failed` или таймауты на всех страницах проекта. Что делать:

1. Поставить свой раннер на машине в РФ: Settings → Actions → Runners → New self-hosted runner.
2. Завести переменную репозитория `RUNNER` с меткой этого раннера: Settings → Secrets and variables → Actions → Variables.

После этого задания проверок пойдут через этот раннер.
